## Context

收銀台系統目前已有完整的結帳功能，包括商品管理、購物車操作和支付方式選擇。根據需求，需要在按下「結帳」按鈕後增加確認總結畫面，讓店員可以再次檢視訂單資訊。

## Goals / Non-Goals

**Goals:**
- 在結帳流程中插入確認步驟，減少操作錯誤
- 提供直觀的訂單總覽介面
- 保持與現有收銀台系統相容

**Non-Goals:**
- 不修改現有的購物車管理功能
- 不改變庫存扣減邏輯
- 不修改支付方式選擇機制

## Decisions

### 彈窗實現方式
**選擇：** 使用現有的 Modal/Dialog 組件實現確認彈窗
**替代方案：** 
- 使用新的路由頁面（不適合，因為這只是臨時確認畫面）
- 使用 Toast 通知（不適合，因為需要使用者明確確認）

### 資料來源
**選擇：** 從購物車狀態物件擷取訂單資訊
**理由：** 避免重複計算金額，確保顯示的資訊與實際待結帳內容一致

### 金額計算時機
**選擇：** 在彈窗開啟時即時計算並顯示
**理由：** 確保顯示的金額是最新的，包含任何剛剛進行的操作

## Risks / Trade-offs

[風險] 使用者可能誤觸「取消」按鈕導致未及時結帳
→ **緩解措施：** 「確認結帳」按鈕使用醒目顏色（如綠色），「取消」按鈕使用中性色

[風險] 彈窗顯示時間過長影響作業效率
→ **緩解措施：** 提供明確的操作指引，避免不必要的延遲
